## 已修复的 Bug

1. **Windows 路径长度限制**: stem_splitter 在 temp 下嵌套 3 层同名目录，长文件名超 260 字符。修复: 用 MD5 hash 生成短临时目录名，长文件名 copy 为短名传入
2. **GBK 编码错误**: 文件名含特殊字符（如 é, ç）导致 print 崩溃。修复: stdout/stderr 设为 UTF-8
3. **目录结构丢失**: 旧版 batch_convert.py 传 target_root 而非 output_dir 给 stem_infer。已修正
4. **临时文件堆积**: 添加 GC + 重试清理机制
5. **C盘空间不足**: 临时文件 73GB 撑爆 C 盘。修复: 临时目录迁移到 D 盘 (`D:\stem_amt_temp`)
6. **stem 分离器 skip_existing 导致无输出**: 分离器检测到已有 stem 文件就跳过，但短文件名导致 resolve_stem_paths 找不到。修复: `skip_existing=False`
7. **MIDI 写入路径超长**: `mido.save()` / `pretty_midi.write()` 在路径 >200 字符时失败。修复: `_safe_path()` 截断输出文件名到 200 字符以内
8. **Python __pycache__ 缓存旧代码**: 修复代码后进程仍使用缓存的旧 .pyc。修复: 运行前清除 `__pycache__`
9. **空 stem 导致 resample 崩溃**: 部分音频的 stem（bass, other, vocals）为空文件，torchaudio.resample 崩溃。修复: try/except 跳过空/bad stem
10. **stdout 双重 wrap 导致 I/O closed**: `stem_infer.py` 和 `infer.py` 各自 wrap stdout 为 UTF-8，GC 关闭第一个 wrapper 后所有 print 崩溃。修复: `_fix_stdio()` 检查 `sys.stdout.encoding == 'utf-8'` 则跳过
11. **stdio 不刷新**: `run_fantasy_stem.py` 的 `TextIOWrapper` 缺少 `line_buffering=True`，子进程输出看不到。修复: 添加 `line_buffering=True`

## 鼓声检测问题（2026-06-07 调查）

### 现象

- 本地分轨模式输出 MIDI 中没有任何 `is_drum=True` 的乐器轨道
- Colab 最新版（2026-06-07 测试 Crazy Baby）同样没有鼓声
- Colab 旧版（2026年5月前）有鼓声（理查德克莱德曼音乐验证）
- 快速模式也完全没有鼓声

### 根因分析

1. HuggingFace 上的 checkpoint（`best_model.pth` 等）**缺少 `interval_instrument_predictor` 权重**
2. 代码有该模块的架构（`models/model.py`），但 checkpoint 只有旧的 `instrument_classifier`（34类输出）
3. 加载时输出: `Missing keys: interval_instrument_predictor.*` → `Falling back to the legacy framewise instrument classifier`
4. 旧分类器（34类）几乎不会将任何音频分类为 drums（instrument_id=7）
5. `INSTRUMENT_CLASSES` 有 35 类，但分类器只输出 0-33（index 7 在范围内但不被选中）
6. GitHub changelog: `2026-05-06 | 🥁 Improved drum detection` — 可能是引入新架构但未上传对应权重

### 修复方案: 鼓声 stem 用 onset detection 替代 AMT

**文件**: `stem_infer.py` 新增 `transcribe_drum_stem()` 函数

不再用 AMT 模型转录鼓声 stem，改用频段滤波 + onset detection：
- 底鼓 (20-200Hz) → GM 36 (Bass Drum 1)
- 军鼓 (150-300Hz) → GM 38 (Acoustic Snare)
- 通鼓 (300-800Hz) → GM 45 (Low Tom)
- 踩镲 (5000-20000Hz) → GM 42 (Closed Hi-Hat)

**已知的待修正问题**:
- ~~大多数底鼓被误检为军鼓（频段重叠，需要更好的频段分割或特征区分）~~
- ~~总检测数偏多，阈值需进一步调优~~

### 优化后参数（2026-06-07 v2）

改动:
1. snare 频段从 150-300Hz → **200-500Hz**（避开 kick 泛音区）
2. kick 阈值从 3.0→**2.5**（更灵敏），snare 从 3.0→**3.5**（更严格）
3. 新增**交叉抑制**：snare onset 如果 kick 频段 ±30ms 内也触发，则判定为底鼓

|------|----|----|----|-----|-------|
| v1 原始 | 360 | 468 | 413 | 270 | 1511 |
| v2 优化 | **585** | **331** | 413 | 270 | 1599 |

## 五、新版官方分轨流程

来源: `newversion-20260726/Colab_Inference.ipynb` 单元[10] `run_stem_separated_transcription()`

```
1. stem 分离（6 个 stem: bass/drums/guitar/other/piano/vocals）
2. 各 stem 用专用模型转录:
   - drums  → best_model_drums.pth
   - bass   → best_model_bass_v2.pth
   - vocals → best_model_vocal_harmony.pth
   - guitar → best_model_guitar_v1_5.pth
   - other  → best_model_other.pth
   - piano  → best_model.pth (default)
3. 合并 MIDI
4. 力度预测（predict_velocity_for_stem_midis）
5. 输出带力度的 MIDI
```
